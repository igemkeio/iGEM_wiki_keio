# 実装指示書: #38 GitLab CI、Vercel、GitHub Actions の CI を新構成に合わせる

Issue: https://github.com/igemkeio/iGEM_wiki_keio/issues/38
設計メモ: docs/architecture.md(「配信パス」「テスト」「運用」)
前提: `origin/feature/vite-mpa` から `feat/38-ci` を切る。#37(E2E)が並行して進むので、E2E のジョブは #37 が後から足す。この Issue では E2E 以外のジョブを作る

## 目的

提出先の GitLab Pages でビルドが通るようにし、Vercel のプレビューと GitHub Actions の CI を新構成に揃える。

## 変更範囲

- `.gitlab-ci.yml`: 全面的に書き換える。`image: node:24`、`cache` に `web/node_modules/`(key は `package-lock.json` のハッシュ)、script は `cd web && npm ci && WIKI_BASE=/$CI_PROJECT_NAME/ npm run build && WIKI_BASE=/$CI_PROJECT_NAME/ npm run check && mv dist ../public`。`artifacts.paths` は `public`。`rules` は既存どおり既定ブランチだけ。GitLab のプロジェクト名(URL の末尾)はまだ不明なので、`$CI_PROJECT_NAME` で動的に取る(iGEM の wiki は `https://2026.igem.wiki/<team>/` で配信され、GitLab のプロジェクト名が `<team>` に一致する前提。README にその前提と、違っていたときに直す場所を書く)。フォントと画像の `WIKI_FONT_BASE`、`WIKI_IMAGE_BASE` は、`static.igem.wiki` の URL が決まるまで未指定(base 付きの `/fonts`、`/images`)
- `vercel.json`: `installCommand` を `cd web && npm ci`、`buildCommand` を `cd web && npm run build && npm run check`、`outputDirectory` を `web/dist`。`framework` は `null` のまま。Vercel のプロジェクト設定で Root Directory が `web` になっているかは不明なので、両方で動く形(`cd web` を付けて、`outputDirectory` はリポジトリ直下からの相対)にし、README にどちらの設定を前提にしたかを書く
- `.github/workflows/ci.yml`(新規): `pull_request` と `push` の `feature/vite-mpa` と `main`。ジョブは `typecheck`、`test`(Vitest)、`test-scripts`(`test:sync` と `test:check`)、`build-check`(`npm run build && npm run check` を `WIKI_BASE=/` と `WIKI_BASE=/keio/` の2回)を並列に、最後に集約ジョブ `ci-passed`(`needs` で全部を待ち、`if: always()` で失敗を伝える)。Node は `.node-version`、npm のキャッシュ。E2E のジョブは #37 が足すので、`ci-passed` の `needs` に後から `e2e` を足せる形にしておく(コメントで示す)
- `main` の ruleset: `ci-passed` を必須チェックにする。これは `gh api` で設定できるが、この Issue では YAML だけを作り、ruleset の変更はメインセッションが行う(PR 本文に手順を書く)
- `web/README.md`: CI と配信の節
- `.github/PULL_REQUEST_TEMPLATE.md`: `yarn dev`、`yarn lint` の記述を `npm run dev`、`npm test`、`npm run check` に直す(小さいので一緒に)

触らないファイル

- `web/src/`、`web/scripts/`、`content/`、`notion-sync.yml`(#39 で済み)、`CLAUDE.md`、`CONTRIBUTING.md`、`README.md`(#41)

## 受け入れ条件

- `.gitlab-ci.yml` と `ci.yml` が YAML として読める。`ci.yml` は PR を作った時点で実際に走る(このブランチの PR で確認する)ので、全ジョブが緑になること
- `vercel.json` の変更で、PR のプレビューが新構成でビルドされる(Vercel の連携が動いていれば PR にコメントが付く。動いていなければその旨を報告)
- `.gitlab-ci.yml` は GitLab の URL が未確定のため実行確認できない。script をローカルで同じ手順(`WIKI_BASE=/keio/ npm run build && npm run check && mv dist public`)で流して通ることを確認する
- README に、GitLab の URL が決まったら確認する項目(プロジェクト名と base の一致、Pages の設定)が書いてある

## 規約

- コミットは `ci:` と `docs:` で分ける(GitLab、Vercel、GitHub Actions、テンプレート、README)
- 日本語、太字とカギ括弧なし、英単語の両端のスペースなし
- Claude の痕跡を付けない
- PR は作らず、push して本文の案を報告する
